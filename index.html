⚠️ 真实踩坑记录与极致避坑指南

在搭建和初次部署时，遇到了几个极为经典的报错，在此整理成血泪避坑指南：

🛑 坑一：安装 Git 部署插件时 npm 意外崩溃

  • 报错现象： 运行 npm install hexo-deployer-git --save 时弹出一大串红字：npm error Cannot read properties of null (reading 'matches')。

  • 原因分析： 本地 npm 缓存严重混乱，或项目根目录残留了不兼容的锁文件。

  • 终极解法： 彻底大扫除！直接在终端运行以下组合命令，删掉冲突文件并强制洗干净本地缓存，然后再重新安装：

🛑 坑二：部署时遇到 Permission Denied 拒绝访问

  • 报错现象： 运行 hexo d 提示 git@github.com: Permission denied (publickey). fatal: Could not read from remote repository. 且报错 Error: Spawn failed。
  • 原因分析： 配置文件里写的是 SSH 格式的地址（git@github.com:...），但本地电脑压根没有配置或绑定过 GitHub 的 SSH 公钥。
  • 终极解法：
    • 最快解法（推荐）： 放弃 SSH，改用更容易通过的 HTTPS 协议。直接打开 _config.yml 把 repository 这一行改成 https://github.com/你的用户名/你的用户名.github.io.git。首次推送时直接点击弹窗授权 GitHub 登录即可。
    • 硬核解法： 在本地终端运行 ssh-keygen -t ed25519 -C "你的邮箱" 生成公钥，通过 cat ~/.ssh/id_ed25519.pub 复制其内容，进入 GitHub 官网 Settings -> SSH and GPG keys -> New SSH key 把它粘贴进去绑定。

🛑 坑三：网页部署成功，但图片全裂开了

  • 报错现象： 本地用 Typora 写文章时截图看得好好的，一推送到 GitHub 线上，文章里的所有图全部显示成红叉或无法加载。
  • 原因分析： 图片默认使用了本地电脑的绝对路径（如 C:\Users\admin\...），传到网上后服务器无法识别。
  • 终极解法： 必须在站点的 _config.yml 中开启资源文件夹功能 post_asset_folder: true。同时，进入 Typora 的 设置 -> 图像 菜单，将插入图片行为严格设置为 “复制到当前图片所在文件夹”，并务必勾选 “优先使用相对路径”。这样生成的路径才会长成标准的相对格式 ![](文章同名文件夹/图片名.png)。

🛑 坑四：安装 hexo-cli 或全局审批脚本时提示不匹配 (ENOMATCH)

  • 报错现象： 执行 npm approve-scripts hexo-util 时报错 npm error No installed packages match: hexo-util。

  • 原因分析： 你的 hexo-cli 是通过全局（-g）安装的，npm 默认会在当前本地目录下寻找该依赖，从而导致找不到匹配包。

🛑 坑五：hexo init 依赖安装失败，抛出 ERR_PNPM_IGNORED_BUILDS

  • 报错现象： 初始化博客时提示 Ignored build scripts: hexo-util... 并警告失败，要求使用 npm install。

  • 原因分析： 本地环境的 pnpm 开启了严格的构建脚本安全限制，拦截了 Hexo 依赖项（如 hexo-util）自动执行的 postinstall 编译脚本。
